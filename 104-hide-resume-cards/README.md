# 104 履歷掃描與篩選系統

這個資料夾提供 104 VIP 人才搜尋頁使用的 Tampermonkey 腳本。前端負責以自然滾動及自動換頁收集完整搜尋結果、呼叫公司限定的 Google Apps Script 評分服務，並呈現推薦、人工覆核與排除結果。

## 安裝

1. 安裝 Tampermonkey。
2. 開啟 [`104-hide-resume-cards.user.js`](./104-hide-resume-cards.user.js)，將完整內容貼入 Tampermonkey 並儲存。
3. 先以公司 Google 帳號開啟腳本內設定的 Apps Script Web App，確認已登入。
4. 重新整理 104 VIP 人才搜尋結果頁，右下角會顯示「104 掃描」。
5. 選擇職缺後執行掃描；結果會分為「推薦」、「人工覆核」、「排除」與「全部」。

  - 產品驗證
  - 自動化測試

- 純軟體測試職稱（例如「軟體測試工程師」、「Software QA」、「SDET」）可直接作為 QA 軟體測試證據，不會因詳情未載入而自動進人工覆核。

## 主要行為

- 掃描完整搜尋結果；每頁先自然滾動等待延遲載入，再自動翻到下一頁。
- 已有人工備註、原生已讀、腳本曾開啟，以及近三個月已主動聯繫的履歷都會先隱藏並跳過，不送後端評分。
- 尚未跳過的履歷會先嘗試 HTTP 詳情補抓，再送公司限定後端評分；詳情資料只存在本次頁面記憶體，不會永久保存。
- 後端負責規則、資格、加扣分與最終分類；前端不保存或下發完整評分權重。
- 排除履歷會從 104 主要卡片列表隱藏，但仍可在掃描面板的「排除」分頁查看。
- 結果依後端總分由高到低排序，並支援批次開啟未讀候選人。

## QA 分類重點

- 最近工作具 Web、App、API、軟體測試、Software QA 或 SDET 證據者，才視為純軟體 QA 候選人。
- 明確硬體、韌體、BIOS、GMS、設備或產品驗證方向會排除。
- 鴻海、廣達、英業達、緯創、仁寶等硬體／軟韌體製造背景仍會扣分並依其他證據決定是否人工覆核。
- QA 總年資達 10 年會保留 OverQualified 人工覆核提示，供確認職等與預算。
- Android、iOS、BIOS、Golang 後端等近期明確非 QA 方向，依既有規則排除。

## 安全與資料邊界

- Apps Script Web App 僅允許公司網域帳號存取。
- 履歷評分資料只送至公司限定的後端；請勿將履歷內容貼入未經公司核准的第三方服務。
- 腳本不會自動邀約、傳訊或送出任何聯絡動作。
- `RULES_API_URL` 屬部署設定；更新時請確認指向正確的正式環境。

## 驗證清單

更新腳本後，建議在 104 QA 搜尋頁抽查：

1. 一般「軟體測試工程師」不會只因詳情缺失而進人工覆核。
2. 「軟韌體驗證工程師」會進排除。
3. 「產品驗證工程師／產品驗證測試工程師」會進排除。
4. 「自動化測試工程師」會進排除。
5. 仍有其他真實風險（例如 OverQualified、薪資或公司風險）者，仍會保留人工覆核。
6. 任一有人工備註的卡片會立即隱藏，掃描完成數只包含未跳過履歷。
7. 抽查前兩份工作，確認每份公司的工作內容沒有互相混用。
8. 以履歷代碼回查有備註的人選時，標籤應顯示「#具備註跳過篩選」，滑鼠移入可查看備註原文。
9. 掃描中的「可分析 + 跳過」不得超過搜尋結果原始總數，且可分析分子不得大於分母。
10. 掃描開始後職缺選單應消失並顯示詠唱提示；掃描結束後恢復原職缺選單。
11. 未掃描前不顯示批次開啟按鈕；完成掃描且有未讀結果時才顯示。
12. 搜尋結果超過 50 筆時，掃描應在第一頁自然載入完成後自動切換下一頁，最終處理數不應固定停在 50。
